The one sentence. Fraud is a decision taken at transaction time; risk is a probability that must survive calibration and a decline that must survive an explanation — so this packet measures a different model on different metrics, and Phase 0 does not close until the base has one number on a public harness, read beside a calibrated reference, with the explanation duty either measured on a public benchmark or published as UNMEASURED.

0. Read this first

What this packet is. Phase 0 for Model 2, in the same lane and on the same machinery as the fraud packet: the capability map fixed before data work, the public benchmarks that exist and the ones that do not, the metrics that count for an imbalanced default prediction, the base shortlist under the 5 B rule, and the frozen protocol the base will be scored on.

What it is not. It is not a corpus, not a weakness map, and not a score. No language model has been run. Everything below that is a number is either a property of the data (prevalence, power, baselines) or a property of the reference model (a gradient-boosted control), and both are labelled. The one cell that matters — the base's calibrated PD — is empty and marked UNMEASURED.

Why risk is a separate model. The owner's instruction is explicit and the measurement agrees: fraud is scored per transaction against a 0.17 % base rate and lives or dies on recall at a staffable alert volume; risk is scored per application against a 4.8–30 % base rate and lives or dies on a probability that a pricing and provisioning system can consume, plus a reason a regulator will accept. Same lane, same provenance machinery, different job, different measures, different model. Neither packet borrows the other's numbers.

What already exists. The fraud lane built the licence register, the provenance gate, the decontamination engine and the split-by-family discipline; those carry over unchanged (§1). The risk corpora are already acquired, hashed and licence-verified (pack/, 75,095 rows across four corpora). German Credit's split is a published OpenML fold file, and this packet proves the join to it row for row (§3). What does not exist is the base measurement, and it is blocked on compute.

Five rules this packet does not bend.

# Rule What it forbids
1 One protocol, frozen before the run Choosing the metric or the split after seeing which flatters

3.1 German Credit — the official harness, and the join that had to be proven

OpenML task 31 publishes a fold-assignment file for the 1,000-row German corpus: 10 folds, 100 test rows each, and the file is the harness — not a re-implementation of 10-fold CV that might differ in seed or stratification.

Two joins had to be proven before the folds could be used:

  1. Row order. OpenML's own ARFF for dataset 31 was compared to the curated parquet: every one of the seven numeric columns and the class agree row for row, 0 mismatches. The curated file preserves publisher order, and the publisher's order is OpenML's order.
  2. Index base. The split file's rowid is 0-based. Joined as 0-based, the folds are class-stratified at exactly 30 bad in every 100-row fold — the publisher's stratification reproduced exactly. Joined as 1-based, every row shifts by one and the positives scatter over 22–36 per fold. The exact 30/30 is independent evidence that the join is right.

Both proofs are in out/split_report.json. A failed proof makes split.py refuse to write folds.

What German is good for: protocol conformance, a published cost metric, and a corpus small enough to iterate on. What it is not good for: a model-comparison verdict (§6 — at n = 1,000 and 300 bad, a 0.02 AUC gap is detected with 14 % power).

3.2 Taiwan default — no official harness, so a named lane protocol

OpenML carries dataset 42477 but only a clustering task (254211), verified against the API. There is no publisher split and no supervised task, so there is no official harness to run. Pretending otherwise would be the exact defect the Recipe names.

The lane therefore pre-registers one: stratified 5-fold × 2 repeats, seed 20261111, plus a frozen 80/20 holdout (n = 6,000, 1,327 defaults, prevalence 22.1167 %). Fold and holdout hashes are in the registration. Every number from it is labelled lane protocol — not an official harness, and no table quotes it without that label.

This is the same position the fraud lane holds on ruling R2 (is a reconstructed FDB split "official"?), and it is Ronin's call, not this packet's. The difference is that here the answer is already known to be no official harness exists, so the honest fallback is a frozen protocol, not a reconstruction claim.

4. Metrics that count — and the accuracy trap, measured

The owner's instruction is that accuracy alone is not a metric. On this lane it is worse than uninformative; it is inverted. Both corpora reward the model that predicts nothing.

Corpus Predict "no default" every time Accuracy ROC-AUC Defaults caught (of all) Brier
German (30.0 % bad) all good 70.0 % 0.500 0 of 300 0.300
Taiwan (22.12 % default) all good 77.9 % 0.500 0 of 6,636 0.221

A 77.9 %-accurate model with zero skill is the single most quotable wrong number available on this lane. So the battery is fixed to three kinds of number, none of which is accuracy:

  1. Rank metrics, threshold-free — ROC-AUC (primary; it is the industry statistic and the metric the one large public risk benchmark is scored on) and PR-AUC (co-primary, because prevalence ranges from 4.8 % to 30 % across this lane's corpora and AUC hides that).
  2. One decision-relevant operating point — recall at a fixed decline rate (5 / 10 / 20 %), because that is the decision a lender actually makes, plus expected cost per applicant under the publisher's 5:1 cost matrix (german.doc §8).
  3. One calibration number — Brier against the base-rate Brier, plus the slope and intercept of y ~ sigmoid(a + b·logit(p)), plus ECE (equal-width and equal-count, because 20 % prevalence against 0.2 % fraud prevalence breaks equal-width bins).

5. Calibration — the duty that separates risk from fraud

A fraud score can be a ranking: the alert queue is sorted, and nobody prices a transaction from it. A default probability is used as a number — it sets pricing, provisioning and capital. A model that ranks well but reports 0.40 when the truth is 0.20 is not a risk model, it is a ranking with a number attached.

The reference model demonstrates the failure, on the official harness, today:

German, official OOF ROC-AUC Brier Brier skill ECE Calibration slope Intercept Cost
Reference, raw output 0.771 0.180 0.143 0.118 0.409 −0.232 0.673
Reference, Platt-recalibrated 0.769 0.166 0.209 0.033 1.037 0.024 0.582

A slope of 0.41 means the raw probabilities are roughly 2.4× too confident in their spread; ECE 0.118 means an 11.8-point average gap between predicted and observed risk. Recall is unchanged (0.267 both ways) because Platt is monotone — the ranking was never the problem, and only a calibration metric sees the defect. After recalibration the slope is 1.04 and the average cost falls from 0.673 to 0.582 per applicant: 13.5 % of the operating cost was a calibration error, not a discrimination error.

Taiwan tells the milder version: raw slope 0.900, Brier 0.1348 against base-rate 0.1723, ECE 0.0143 — already close to calibrated, and Platt moves it to slope 1.062 without improving Brier. The lesson is that calibration quality is corpus-dependent and cannot be assumed in either direction.

The protocol, frozen:

  1. Platt scaling is fitted on inner out-of-fold scores inside the training folds only.
  2. It is applied to the held-out fold, never refitted on it (V4 voids the run).
  3. Both raw and recalibrated numbers are published side by side. Reporting only the recalibrated number hides a model defect; reporting only the raw number hides a usable PD.
  4. Gate G2: Brier ≤ base-rate Brier − 0.01 and slope ∈ [0.80, 1.25] and |intercept| ≤ 0.10. A model that fails G2 may still be reported for R1 (ranking) — but it is not a PD and the verdict says so.

6. Power — what each benchmark can decide

Bootstrap of the frozen out-of-fold reference predictions, 1,000 resamples, seed 20261111. Full receipt in out/power.json.

Evaluation set n defaults SE(AUC) 95 % CI half-width MDE vs a model (80 %) power of a 0.02 gap
Taiwan, pooled OOF 30,000 6,636 0.0035 ±0.007 0.014 0.981
Taiwan, frozen holdout 6,000 1,327 0.0075 ±0.015 0.030 0.470
German, pooled OOF 1,000 300 0.0159 ±0.030 0.063 0.142
German, single fold 100 30 0.0417 ±0.082 0.165 0.053

Read it as three sentences.

  1. Taiwan can decide a 0.02 AUC difference (power 0.98). That is the only evaluation set on this lane that can support "the base beats the reference" or "it does not".
  2. German cannot (power 0.14). Its official harness is the better-established instrument and the weaker measuring one; a verdict read off German is a coin flip with a citation.
  3. A single fold is never quoted. Fold 0 of German scores AUC 0.844 against 0.771 pooled — the most flattering cell in the battery, and an accident of 30 positives in 100 rows. Per-fold spread is 0.696–0.844 (SD 0.047) on German against 0.767–0.788 (SD 0.008) on Taiwan.

This is the fraud lane's lesson applied before the mistake is made: a gate read as a model comparison at low power is not a test. The fraud lane discovered that a +0.10 PR-AUC gate had 36 % power; here the number is written down before the run, so no future verdict can quietly read the floor as a win.

7.1 Why Qwen3-4B, and what would overturn it

Three reasons, in order of weight:

  1. One stack. The definitive report §10.4 forbids re-deciding the base per training. The fraud lane already measured and adopted Qwen3-4B; a second base for the second model would create two stacks, two tokenizer behaviours, two sets of prompt hashes, and twice the harness surface.
  2. It fits the job's scoring path. A decoder that gives a clean two-token distribution at a fixed prefix is what R1–R3 need; the fallback 1.7 B is the same architecture and protocol, so a swap would be a documented departure, not a redesign.
  3. Licence and size clear both gates — Apache-2.0, ungated, 4.02 B.

Falsification, written before the run. If the base's calibrated Brier on the German official row does not beat the base-rate Brier (0.210), it is not a probability model at all, and no amount of post-hoc calibration rescues a model whose ranking is noise. If it beats the base-rate Brier but fails G2's slope band, the base is a ranker and the risk product cannot be the language model — the scorer stays the GBM and the model's job becomes explanation only. That is decision row D-R2, and it is the owner's, not this packet's.

On TabPFN. It is a genuinely small tabular foundation model and would be a fair reference on both corpora — small-data accuracy is its design point, and both corpora are small. It is not adopted as the trained model: it is a predictor, not a language model, it cannot emit a reason code, and its licence (Apache-2.0 plus an attribution requirement) has not been cleared for shipping. It belongs in the reference row set beside the GBM once compute exists, and the packet says so rather than quietly omitting it.

7.2 One base, two jobs — the shortlist across the lane

The owner's rule is that each model gets its own packet, not that each model gets its own stack.

Job Scored when Base Headline metric Second metric What the base must not do
Credit Fraud (Model 1) per transaction, 0.17 % base rate Qwen3-4B-Instruct-2507 PR-AUC, recall @ 1 % FPR ROC-AUC Miss fraud at a staffable alert volume

Same weights, same scoring path family, different decision rule and different measures. That is the whole point of the split: the model is shared to keep one stack, the measurement is not shared because the jobs are not the same job. If risk's calibration gate (G2) fails, the risk model changes role — ranker and explainer, with the GBM scoring — and the stack does not change (D-R2).

The only size move that stays inside the protocol is Qwen3-1.7B, which keeps the architecture and the prompt format and halves the inference cost. It is shortlisted rather than adopted because the lane's compute constraint is one 4 B model, not two, and a 1.7 B base would need its own measured row to justify the swap — which is exactly the kind of unmeasured change this packet exists to prevent.

9. The explanation duty — the capability that decides whether this model has a job

Adverse-action explanation is not a nice-to-have in credit; it is the legal condition of declining an application. The Recipe's rule is brutal and correct: home-grown controls belong to the DATA side only — they never produce a model score. A SHAP-agreement diagnostic is a model-side home-grown check. So it is recorded as a diagnostic, excluded from every score table, and the capability publishes as UNMEASURED.

What would measure it: the FICO HELOC xML challenge, the one public benchmark built for exactly this question — reason codes on a credit-decline task. It cannot be used today, for two independent reasons:

  1. Licence. The corpus's licence is recorded as unverified in the pack register; the HF mirror's bare cc is not a licence, and the FICO challenge terms have not been read. The Recipe's Phase 4 rule is absolute: a record whose licence cannot be proven is dropped before the packet, never discovered mid-run.
  2. Protocol. Even with a licence, the challenge's official scoring path is the challenge's; an approximation of it is a variant protocol, and a variant protocol's number is discarded.

The consequence, stated plainly: if explanation is the product — and on this lane it is the only capability a GBM cannot have — then the Recipe cannot currently certify the product. That is not a reason to fake a number; it is a reason to put the licence question to the owner as a decision row (D-R2/D-R4) and to keep measuring R1–R3 in the meantime.

One thing is measurable without the benchmark and is worth stating: the reason channel and the verdict channel share one record format ({"risk": " default", "reasons": […]}), so a model trained on reasons cannot drift from the format its verdict is scored in. That is the same format-match discipline the fraud lane learned the hard way, applied before the training run rather than after.

10. How the base will be measured — the run

Fixed before any data work, in this order. No step is optional and no step may be reordered.

# Step Gate Cost
0 validate_metrics.py → PASS metric engine parity < 1e-9 seconds
1 split.py → join proof + fold hashes refuses on a failed OpenML join seconds
2 protocol.py --check → schema match refuses if the pack gains or loses a column seconds
3 G0 tokenizer check — both verdict tokens are one token blocks the run minutes
4 Pin the Hub revision; record it in the receipt G5 identity minutes
5 Score German, all 1,000 rows, one forward pass each coverage ≥ 0.98 ~1 GPU-minute
6 Score Taiwan holdout, 6,000 rows coverage ≥ 0.98 ~5–15 GPU-minutes
7 Determinism: 200 rows scored twice, identical V3 minutes
8 evaluate.py → R1–R3 numbers, raw and calibrated G1–G4 seconds
9 Publish with the loss mechanisms and UNMEASURED rows intact — —

GPU budget, written before the stage. One 4 B model at bf16, batched: 20–40 rows/s single stream, 200–400 rows/s batched, on one A100-class GPU. The whole battery is 7,000 scored rows — under 0.1 GPU-hour, call it 1 GPU-hour with queueing and a re-run. This is an estimate, and the Recipe requires the estimate before the stage: stop condition — if measured batched throughput is below 50 rows/s, stop and report the throughput rather than burning GPU-days. A full OOF re-scoring of Taiwan (30,000 rows × 2 repeats) would be ~1–2 GPU-hours and is not needed for Phase 0.

What voids the run: a split or prompt hash mismatch (V2); a determinism failure (V3); calibration fitted on evaluation rows (V4); a coverage below 0.98 (G5); a base that fails G1 (no measurable skill — the run is not void, the verdict is "no skill").

What the run does not do: it does not choose the base (D-R1), does not start training, does not touch the corpus, and does not settle whether explanation is the product (D-R2).
